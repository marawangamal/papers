# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

Papers is a semantic search app for ML conference papers (papers.app). It is a Next.js 15 (App Router, React 19, Mantine UI) frontend backed by Supabase (Postgres + pgvector, Edge Functions, Auth). Python scrapers in `scripts/` produce CSVs that are imported into Supabase.

## Common commands

```bash
npm run dev        # Next.js dev server (turbopack) on :3000
npm run build      # production build
npm run start      # run production build
npm run lint       # next lint (there is no type-check / test script)

# Local Supabase (required for dev — app reads from NEXT_PUBLIC_SUPABASE_URL)
supabase start     # starts Postgres + Studio + Edge runtime on :54321
supabase db reset  # apply migrations under supabase/migrations + seed.sql
supabase functions serve  # serve edge functions locally
```

Python scraper tooling lives in `.venv/` at the repo root. Scrapers write to `dumps/<conference>/{venues,papers}.csv`; `scripts/supabase_import.py --path <dump>` pushes them into Supabase.

## Architecture

### Route groups and auth boundary
`src/app/` uses two route groups that separate the auth boundary: `(public)/` (landing, `/login`, auth callbacks) and `(private)/` (`/dashboard`, `/search`). The boundary is enforced by `src/app/middleware.ts` → `src/utils/supabase/middleware.ts`, which refreshes the Supabase session cookie on every request and redirects unauthenticated users hitting private routes to `/login`.

### Supabase client strategy
There are three clients, and mixing them up breaks auth:
- `src/utils/supabase/server.ts` — server components / server actions, reads cookies from `next/headers`
- `src/utils/supabase/client.ts` — browser components
- `src/utils/supabase/middleware.ts` — the edge middleware cookie refresher (do not use elsewhere)

Server actions live in `src/lib/actions/*` and are the primary data-access layer — components should call these, not hit Supabase directly.

### Search pipeline (the core feature)
1. UI posts a query to the `getMatchingPapers` server action (`src/lib/actions/papers.ts`).
2. If `search` is empty, it queries the `vw_final_papers` view directly with filters.
3. If `search` is present, it invokes the Supabase Edge Function `supabase/functions/search/` which (a) embeds the query using `Supabase.ai.Session("gte-small")`, (b) calls the `query_embeddings` RPC (pgvector cosine similarity, threshold 0.8), (c) applies venue/year/has_code filters, (d) paginates.
4. Results are wrapped in `unstable_cache` keyed by all params with `revalidate: 300` and tag `papers` — invalidate via `revalidateTag("papers")` after writes. Each search is logged to `search_logs`.

Embeddings are generated by the `generate-embedding` edge function (invoked from DB triggers / batch jobs, not the request path). `cross-reference-arxiv` enriches papers with arXiv metadata.

### Database
Migrations in `supabase/migrations/` are the source of truth for schema. Key objects:
- `papers`, `venues`, `collections`, `event_log`, `search_logs` tables
- `vw_final_papers` — denormalized view joining papers + venue + like/view counts; most reads go through this
- `query_embeddings(embedding, match_threshold)` RPC — pgvector similarity search

TypeScript types for all tables/views are generated into `src/types/database.types.ts`. Import via `Tables<"name">` / `TablesInsert<"name">` rather than redeclaring.

### Adding a conference scraper
Subclass `ConferenceScraper` in `scripts/base.py` and implement `scrape_year(year)`. Output must be exactly `venues.csv` (name, abbrev, year) and `papers.csv` (title, authors, abstract, venue_abbrev, venue_year, pdf_url, code_url) — authors are pipe-delimited (`|`). See `scripts/scrape_iclr.py`, `scrape_icml.py`, `scrape_pmlr.py` for reference. PR naming: `Feat/add-conference-<year>-<abbrev>`. Maintainers run the scraper and then `scripts/supabase_import.py` to load data — contributors should not push data to the production DB.

## Conventions

- Path alias `@/*` → `src/*` (tsconfig). Supabase edge functions under `supabase/` are excluded from tsconfig and use Deno imports (`jsr:`, `npm:`) — do not try to share code between `src/` and `supabase/functions/` via normal TS imports; copy types into `supabase/functions/_shared/` instead.
- Server actions are marked `"use server"` and live in `src/lib/actions/`. Prefer adding to those files over creating new API routes; `src/app/api/` is used sparingly.
- UI uses Mantine v7 + Tailwind together — Mantine for components, Tailwind for layout utilities. `@mantine/core/styles.css` and `katex/dist/katex.min.css` are imported globally in `src/app/layout.tsx`.
- Deployment target is Railway (`railway.json`); build runs `npm run build`, start runs `npm run start`. CI (`.github/workflows/ci.yaml`) runs lint + build on Node 18/20.

## Commit messages

Follow [Conventional Commits](https://www.conventionalcommits.org/): `<Type>: <Short description>`. Do **not** use parenthesized scopes in this repo (use `Bugfix: ...`, not `Bugfix(test): ...`).

Types used in this repo (capitalized — this repo uses `Bugfix` rather than the standard `fix`):
- `Feat:` — new feature/capability
- `Bugfix:` — bug fix
- `Refactor:` — restructure without behavior change
- `Perf:` — performance improvement
- `Test:` — add/update tests
- `Docs:` — documentation only
- `Chore:` — tooling, ignores, cleanup, deps
- `Revert:` — revert a previous commit

Keep the subject ≤ 72 chars, imperative mood ("Add X", not "Added X"), capitalized after the colon. Add a body only when the *why* isn't obvious from the diff. No Claude co-author trailers.
